### 4. Панель администратора (основной объём)

Итоги разведки (amnezia-client, коммит ac175c8, и живой контейнер amnezia-awg2):

- **HTTP API у Amnezia нет вообще.** Управление — только SSH exec + SCP + `sudo docker exec`. Значит наш выбор (SSH из хелпера) совпадает с оригиналом, других путей нет.
- **Ключи клиента Amnezia генерирует локально** (X25519), на сервер уходит только публичный. Модель «приватный ключ не покидает устройство» уже поддержана серверной частью.
- **Добавление пира** (как делает оригинал): прочитать `awg0.conf` → свободный `/32` → дописать `[Peer]` с `PublicKey`/`PresharedKey`/`AllowedIPs` → применить
  `docker exec -i <c> bash -c 'awg syncconf awg0 <(awg-quick strip /opt/amnezia/awg/awg0.conf)'`.
  **Контейнер не перезапускается.** Отзыв — вырезать секцию по pubkey, тот же `syncconf`, плюс правка `clientsTable`.
- **Внутри контейнера** есть `awg`, `awg-quick`, `bash`, `awk`, `sed`, `flock`, `iptables`; **python отсутствует**; `/opt/amnezia/awg` доступен на запись; контейнер privileged.
- **`awg show all dump`** даёт машиночитаемый TSV (pubkey, psk, endpoint, allowed-ips, handshake, rx, tx) — на нём и строить список пиров.
- Обфускация (Jc/Jmin/Jmax, S1-S4, H1-H4, I1-I5, HeaderProtectionKey) — часть серверного интерфейса, клиент их только копирует. Сгенерировать свои = handshake не пройдёт.
- **Контейнер не переживёт кривой `awg0.conf`**: при рестарте `start.sh` делает `awg-quick down/up` по этому файлу. Запись только атомарная, с бэкапом и проверкой после применения.

Архитектура доступа (решение по безопасности):

1. **Бутстрап** — первое подключение полным SSH (пароль или ключ пользователя), хелпер идемпотентно ставит на сервер:
   пользователя `awgbv` (nologin), `/usr/local/sbin/awgbv-peer` (0700 root), наш ed25519-ключ в `authorized_keys`
   со строкой `restrict,command="sudo /usr/local/sbin/awgbv-peer"`, `sudoers` NOPASSWD строго на этот скрипт.
2. **Пароль используется один раз и не сохраняется** (по умолчанию). Дальше — только наш ключ.
3. **Дальше все операции идут через forced command**: `$SSH_ORIGINAL_COMMAND` = `add --pubkey <44b64> --name X` / `list` / `remove --pubkey …`.
   Никакого shell, только эти глаголы. Аргументы валидируются регулярками, `/32` — из своей подсети.
4. Хост-ключ сервера — TOFU: отпечаток запоминается, при расхождении жёсткая ошибка с показом обоих.
5. Внутри скрипта: `flock` → чтение → `.bak` → атомарная запись `.new` + `mv` → apply → проверка `awg show all dump`, при ошибке откат.

Лицензионная проблема, которую нельзя игнорировать: скрипты Amnezia (`client/server_scripts/*`) — **GPL-3.0**, наш проект — MIT.
Копировать их нельзя, иначе проект обязан стать GPL. Поэтому «полный паритет по контейнерам» делаем **своей реализацией**
(публичные образы `amneziavpn/amneziawg-go` и т.п., свои docker-команды и конфиги), а не копированием их файлов.

Из этого следует этапность: контейнеры — это docker build/run, сети `amn0`/`amnezia-dns-net`, установка docker,
проверки ядра, 12 типов протоколов. В один релиз с панелью пиров это не влезает без риска сломать чужие серверы.
Фаза 1 (0.3.7):

## Открытые вопросы

- иконки: брать Flaticon (нужна атрибуция: автор + ссылка в README и в «О расширении») или рисовать свои SVG без лицензионных обязательств.
- SSH-аутентификация по ключу: где хранить ключ — файл в state-каталоге с правами 600 или `ssh-agent`.
- XRay/OpenVPN в панели: нужны ли их клиентские ссылки в браузере (браузер их не умеет) или только установка на сервер.
